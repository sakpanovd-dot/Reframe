# Reframe

Локальное Python-приложение для Windows: выбрать видео → пропорции и тип файла → «Создать» → выбрать место сохранения. Основной сценарий — **16:9 → 9:16, автоматическая вертикальная заготовка для монтажёра**. Программа анализирует сцены, выбирает объект и перемещает рамку обрезки. Спорные интервалы отмечает в отдельном отчёте; без устойчивого объекта сохраняет полный кадр на размытом фоне.

## Запуск в этом проекте

Окружение `.venv` и модель уже подготовлены на текущем компьютере.

```powershell
.\.venv\Scripts\python.exe -m reframe
# Или:
.\run.ps1
```

Код поддерживает Python 3.11–3.13; проверенная конфигурация — **Python 3.12 x64, Windows**. Python 3.14 для этого окружения не используйте.

При запуске через `run.ps1` или `python -m reframe` ошибка загрузки библиотек/DLL выводит техническую причину и русскую подсказку о восстановлении через `setup.ps1`. Зависимости автоматически не переустанавливаются. Ошибки загрузчика плагинов Qt после импорта могут потребовать отдельной диагностики.

## Установка на другом компьютере

1. Установите Python 3.12 x64.
2. Установите FFmpeg с `ffmpeg.exe` и `ffprobe.exe` в PATH, например `winget install Gyan.FFmpeg`. После установки откройте PowerShell заново.
3. В папке проекта выполните `powershell -ExecutionPolicy Bypass -File .\setup.ps1`.
4. Запускайте `run.ps1` или `.venv\Scripts\python.exe -m reframe`.

Для отдельного проверочного окружения можно запустить `powershell -ExecutionPolicy Bypass -File .\setup.ps1 -EnvironmentPath work\clean-install`. Относительный путь считается от папки проекта. Скрипт проверяет запуск FFmpeg/ffprobe (включая пути `REFRAME_FFMPEG` / `REFRAME_FFPROBE`), версию и разрядность Python, устанавливает зависимости и выполняет `pip check`. В конце выводится команда запуска выбранного окружения. `run.ps1` по-прежнему использует стандартную `.venv`. Существующие окружения автоматически не удаляются.

Установка зависимостей и модели требует интернета. Приложение не скачивает компоненты при обработке и не отправляет видео, журналы или аналитику на сервер. При ручной установке:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
.\.venv\Scripts\python.exe scripts\download_model.py
```

Модели: официальный YOLOX-s (объекты), релиз `0.1.1rc0`, SHA-256 в `reframe/model.json`; YuNet 2023mar из OpenCV Zoo (лица, 232 КБ, MIT), SHA-256 в `reframe/face_model.json`. `download_model.py` ставит обе. После обновления кода на другом компьютере его нужно запустить ещё раз. Загрузчик проверяет хеш до замены файла; приложение повторно проверяет хеш перед анализом. Возможны пути `REFRAME_MODEL` и `REFRAME_FACE_MODEL`, но файлы должны соответствовать манифестам. Пути к FFmpeg можно задать переменными `REFRAME_FFMPEG` и `REFRAME_FFPROBE`.

## Возможности MVP

- 9:16, 16:9, 1:1, 4:5, 4:3; MP4/MOV, H.264 + AAC.
- Входы MP4, MOV, MKV, AVI, WebM и другие контейнеры, которые читает установленный декодер. Вместо ограничения H.264/H.265 программа проверяет декодирование первого кадра через тот же PyAV, что используется при обработке. Проверены SDR H.264/H.265, AV1, VP9, MPEG-4 и ProRes; это не обещание поддержки любого кодека или повреждённого файла.
- Поворот телефона, неквадратные пиксели, переменная частота кадров и видео без звука.
- Оригинальная длительность, порядок кадров и основной звук. Другие звуковые дорожки, вложенные субтитры и служебные метаданные не переносятся.
- При точном совпадении пропорций исходника и результата анализ объектов и сцен пропускается. Такой экспорт работает без модели; проверка файла, кодирование и сохранение звука выполняются как обычно. Учитываются поворот и соотношение сторон пикселя.
- Полезное изображение не увеличивается сверх разрешения исходника; разрешение результата зависит от доступной области кадра. Маленькое широкое видео при переводе в вертикальное может дать небольшой выходной файл — это намеренный выбор качества.
- Превью до и после обработки, прогресс каждого этапа, отмена, безопасное сохранение, кнопки открытия результата.
- Очередь: можно выбрать или перетащить сразу несколько видео, в том числе во время обработки. Они обрабатываются по очереди с выбранными пропорциями. Результат сохраняется без диалога рядом с исходником (или в выбранной папке) как `имя_9x16.mp4`; существующие файлы не заменяются — добавляется номер `(2)`. Ошибка одного видео не останавливает остальные; отмена останавливает очередь, оставшиеся видео ждут. По окончании — уведомление Windows и мигание значка на панели задач.
- Обработка использует половину логических ядер (`REFRAME_THREADS` переопределяет) и работает с пониженным приоритетом Windows, чтобы монтажная программа оставалась отзывчивой.
- Во время обработки плеер сохраняет кадр на паузе; изменения прогресса не меняют источник видео и не отправляют повторные команды паузы. Возможности встроенного плеера могут отличаться от декодера экспорта: ошибка предпросмотра сама по себе не запрещает конвертацию.
- При закрытии во время работы можно отменить задание; окно закроется после очистки временных файлов.

Целевой материал — трейлеры, реклама и сцены до **5 минут / 1080p**. Более длинные или крупные файлы разрешены с предупреждением. Качество важнее скорости; обработка работает отдельным процессом. HDR отклоняется. Нет ручной рамки, распознавания говорящего, очереди заданий или онлайн-сервисов.

### Вертикальная заготовка и проверка монтажёром

Для горизонтального 16:9 при выборе 9:16 автоматически используется отдельная стратегия `editorial`. Она оценивает траектории за всю сцену и начинает обрезку с её начала. Большой объект допускается показывать частично; сопоставимые кандидаты объединяются, если помещаются, иначе выбирается один. Движение вне рамки и быстрое панорамирование отмечаются для проверки вместо автоматического возврата к фону. Рамка постоянного размера, движения через склейки нет. Если выбранный объект обнаружен менее чем в 55% образцов сцены, рамка ставится по лучшей догадке (обнаружения, затем движение) и интервал отмечается в отчёте — размытый фон для живых кадров не используется. Титры и пэкшоты (почти однотонные кадры без людей) вписываются целиком по ширине на продолжении собственного фона. Кадр из нескольких вертикальных панелей (сплит-скрин) показывает одну панель во весь экран и переключается на другую не чаще раза в 2 с, предпочтительно на склейке внутри панели. Движение рамки интерполируется сплайном без остановок между образцами анализа. Лица (YuNet) повышают приоритет человека, который смотрит в кадр, служат лучшей догадкой в сценах без устойчивого объекта, а лицо выбранного героя всегда остаётся целиком в рамке. Вшитые плашки и логотипы поверх живого кадра намеренно не учитываются: монтажёр ставит их отдельно. Проверка удержания лиц: `python scripts/face_report.py DIAGNOSTICS.json`.

После успешного экспорта рядом с видео создаётся уникальный файл `имя.review-<id>.html`. Кнопка **«Проверить интервалы»** открывает его в браузере: таймкоды, сцена, режим и причина проверки. Отчёт не накладывается на видео и не требует интернета. При отказе записи отчёта готовое видео сохраняется, приложение сообщает об ошибке отчёта. В диагностическом JSON также доступны `strategy` и `review`.

Это первый вариант автоматического чернового кадрирования, не профессиональная семантическая оценка. Используется локальная YOLOX-s; OCR, определение говорящего и понимание событий пока отсутствуют. Кроп может потерять надписи, логотипы или важного второго персонажа; отчёт не гарантирует обнаружение всех таких ошибок. Другие сочетания пропорций пока используют прежнюю осторожную стратегию.

### CPU и NVIDIA

CPU работает по умолчанию. NVENC автоматически проверяется коротким пробным кодированием; при недоступности или ошибке используется libx264. Это независимо от ускорения модели.

Для CUDA нужен совместимый NVIDIA-драйвер и GPU-сборка ONNX Runtime **вместо** CPU-сборки. В отдельном проверяемом окружении можно заменить пакет:

```powershell
.\.venv\Scripts\python.exe -m pip uninstall -y onnxruntime
.\.venv\Scripts\python.exe -m pip install "onnxruntime-gpu[cuda,cudnn]==1.31.0"
```

Приложение пытается предварительно загрузить CUDA/cuDNN DLL, затем создать CUDA-сессию. При неудаче возвращается на CPU. На текущем компьютере только Intel Iris Xe: CUDA и NVENC здесь **не прошли аппаратную приёмку**. Совместимость драйверов и библиотек: [официальная документация ONNX Runtime](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html).

## Как устроено

Интерфейс PySide6/QML общается через события с отдельным процессом задания. Процесс последовательно выполняет проверку → анализ → планирование → рендеринг → добавление звука → проверку результата. Отмена передаётся через process event; FFmpeg останавливается и дожидается завершения перед очисткой.

Перед сохранением результата проверяются размеры, длительность и основной звук, затем FFmpeg полностью декодирует видео и звук без создания ещё одной копии. Ошибка чтения не позволяет заменить существующий результат. Этап «Проверка результата» поддерживает отмену; его время зависит от длины и разрешения файла.

Анализ использует кадры с длинной стороной не более 640 пикселей, детектор около 5 раз в секунду и проверку смены сцен на каждом декодированном кадре. Координаты переводятся обратно в исходное пространство. Связывание объектов использует класс, прогноз движения и пересечение рамок. Главный объект выбирается по уверенности, размеру, положению и стабильности.

Границы сцен учитывают изменение композиции, цвета и недавнее движение. Один следующий кадр помогает исключать одиночные вспышки; проверка сдвига и сохранения фона уменьшает ложные склейки. Отдельная карта движения защищает от ситуации, когда модель выбрала неподвижный фон, а заметное действие происходит вне рамки. При этом движение самого выбранного объекта учитывается отдельно и не запрещает слежение. Это эвристики: очень резкое движение, перекрытия и стилизованная анимация всё ещё могут давать ложные склейки или неверные обнаружения.

Рамка имеет постоянный размер. Центральная зона допускает небольшое движение без панорамирования. Траектория сглаживается внутри сцены. В основной стратегии 16:9 → 9:16 быстрые движения, частично показанный объект и конкурирующая активность отмечаются в отчёте. В остальных форматах сохраняются прежние ограничения: быстрые движения и неоднозначность могут включать полный кадр, короткие чередования режимов подавляются. Выбор пока не учитывает звук или сюжетный смысл.

Основные контракты — `VideoInfo`, `AnalysisResult`, `ReframePlan`, `ExportRequest`, `ProgressEvent` в `reframe/contracts.py`. Анализатор не зависит от пропорций и контейнера; рендерер не знает о детекторе; интерфейс не содержит алгоритма кадрирования.

### Добавление формата

- **Новые пропорции:** добавить запись в `reframe/presets.json`: `id`, `title`, `width`, `height`, `description`. Ширина/высота задают предельный размер. Интерфейс строит карточки из этого файла.
- **Новый контейнер:** добавить адаптер в реестр `EXPORTERS` в `reframe/export.py` и проверку его кодеков/мультиплексирования. Существующие MP4/MOV используют общий адаптер; произвольный контейнер может потребовать собственной реализации финализации.
- **Новая модель:** реализовать протокол `Detector.detect(image) -> list[Detection]`, сохранив координаты и уверенность; планировщик и экспорт не меняются.

Состояние GUI сохраняется в `settings.json`, технический журнал — `work/reframe.log`. Журнал включается при запуске приложения и содержит в том числе ошибки открытия исходника; при отказе в доступе интерфейс предлагает проверить права или скопировать файл в доступную папку. При обычной ошибке временная папка `.reframe-<id>` рядом с результатом удаляется. При принудительном завершении через диспетчер задач или отключении питания папка может остаться; исходник и существующий результат сохраняются.

При временной блокировке файлов очистка повторяется до трёх раз. Если папка всё ещё недоступна, её путь записывается в журнал: готовое видео остаётся успешным результатом, а ошибка очистки не заменяет причину неудачи или отмену. Такая временная папка может остаться до ручного удаления после завершения задания. Перед публикацией результата программа повторно проверяет защиту исходника и запрет неподтверждённой замены.

Повреждённые или неподдерживаемые настройки не мешают запуску: используются 9:16 и MP4, а корректные поля сохраняют своё значение. Настройки записываются через временный файл; при отказе в записи экспорт продолжается, но выбор может не сохраниться к следующему запуску. Если `work/reframe.log` недоступен, приложение и процесс обработки направляют журнал в консоль запуска. При запуске без доступной консоли эти сообщения могут быть недоступны для просмотра; запасной файл в другой папке не создаётся.

## Проверка и диагностика

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts\smoke_ui.py
.\.venv\Scripts\python.exe -m reframe.cli input.mp4 output.mov --preset 9:16 --cpu --diagnostics work\plan.json
```

`--overwrite` явно разрешает замену результата. `--fit-only` — только диагностический режим CLI, отключающий модель; в продуктовый интерфейс он не вынесен.

В диагностическом JSON у кадров плана есть поле `reason`: например, `tracking`, `ambiguous`, `subject_too_large`, `motion_outside_crop`, `fast_motion` или `stabilizing`. Оно объясняет решение планировщика, но не доказывает правильность выбранного объекта. Старые диагностические файлы без этого поля также читаются инструментом просмотра.

При пропуске анализа поле `analysis.backend` равно `skipped_same_ratio`. Единственный образец описывает постоянную рамку на всю длительность, а не утверждает, что в исходнике одна монтажная сцена.

При изменении пропорций полностью одинаковые изображения повторно используют последнее распознавание. Сравнение точное, по всем пикселям: даже небольшое изменение запускает модель снова. Трекинг и поиск склеек продолжаются с прежней частотой. Это ускоряет фрагменты с неподвижным изображением; на непрерывном движении выигрыш не гарантирован. В памяти хранится только последний уменьшенный кадр и его обнаружения.

Для воспроизводимого сравнения CPU-анализа: `python scripts/benchmark_analysis.py VIDEO --repeats 2 --output work/analysis-benchmark.json`. Инструмент чередует запуски с повторным использованием распознавания и без него, считает обращения к модели и проверяет точное совпадение анализа и планов всех пресетов. Время загрузки модели и экспорта в этот замер не входит. Не запускайте другие тесты или конвертацию одновременно с замером.

Для сопоставления исходника с готовым экспортом: `python scripts/review_video.py SOURCE RESULT DIAGNOSTICS --output work/video-review`. Инструмент создаёт локальные контактные листы, длительности режимов и причин решений. Для отдельного повторного прогона инженерного набора: `python scripts/inspect_quality.py --diagnostics work/samples/release-quality.json --output work/samples/release-check`. План оставшихся работ — `ROADMAP.md`.

Для инженерной проверки подготовлены `quality_corpus.py`, `inspect_quality.py` и `benchmark.py`. Первый создаёт 12 сцен с управляемым движением из реальных демонстрационных фотографий; второй считает удержание объекта и создаёт контактный лист; третий проверяет 1080p и длинный файл. Исходные фото необходимо заранее поместить в `work/samples`:

- `dog.jpg`: [пример YOLOX](https://raw.githubusercontent.com/Megvii-BaseDetection/YOLOX/main/assets/dog.jpg).
- `people.jpg`: [пример YOLOv5](https://raw.githubusercontent.com/ultralytics/yolov5/master/data/images/zidane.jpg).

Фото используются только для локальной диагностики; папка `work` не входит в поставку исходного пакета. Они не являются разнообразным набором реальных пользовательских видео. Смешанная приёмка на твоих исходниках и оценка субъективного качества остаются отдельным шагом.

Подробные результаты и ограничения — в `TESTING.md`.

Длительный прогон с настоящей моделью на Windows: `python scripts/soak_test.py work/samples/corpus.mp4 --seconds 600`. Инструмент повторяет подготовленный набор сцен, добавляет звуковые метки в начале и конце и экспортирует в 9:16 на CPU. После экспорта проверяет все временные метки и число кадров, положение звуковых меток и очистку временных файлов. Каждый запуск создаёт отдельную папку в `work/soak` с исходником, результатом, планом и отчётом; существующие материалы не перезаписываются. Пиковая память относится к процессу Python, без дочерних FFmpeg и интерфейса. Это проверка длительной работы на повторяемом материале, не приёмка качества на разнообразных реальных видео и не замер 1080p.

Для нагрузки 1080p у исходного набора 16:9 добавьте `--width 1920`. В отчёте сохраняются фактические ширина и высота тестового файла. Увеличение технического исходника проверяет декодирование и экспорт при таком разрешении, но не добавляет деталей изображения и не заменяет проверку настоящих 1080p-съёмок.
