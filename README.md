# Reframe

Локальное Python-приложение для Windows: выбрать видео → пропорции и тип файла → «Создать» → выбрать место сохранения. Дальше программа анализирует сцены, выбирает главный объект и плавно перемещает рамку. При неоднозначной сцене сохраняет весь исходник на размытом фоне.

## Запуск в этом проекте

Окружение `.venv` и модель уже подготовлены на текущем компьютере.

```powershell
.\.venv\Scripts\python.exe -m reframe
# Или:
.\run.ps1
```

Код поддерживает Python 3.11–3.13; проверенная конфигурация — **Python 3.12 x64, Windows**. Python 3.14 для этого окружения не используйте.

## Установка на другом компьютере

1. Установите Python 3.12 x64.
2. Установите FFmpeg с `ffmpeg.exe` и `ffprobe.exe` в PATH, например `winget install Gyan.FFmpeg`. После установки откройте PowerShell заново.
3. В папке проекта выполните `powershell -ExecutionPolicy Bypass -File .\setup.ps1`.
4. Запускайте `run.ps1` или `.venv\Scripts\python.exe -m reframe`.

Установка зависимостей и модели требует интернета. Приложение не скачивает компоненты при обработке и не отправляет видео, журналы или аналитику на сервер. При ручной установке:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
.\.venv\Scripts\python.exe scripts\download_model.py
```

Модель: официальный YOLOX-s, релиз `0.1.1rc0`, SHA-256 в `reframe/model.json`. Загрузчик проверяет хеш до замены файла; приложение повторно проверяет хеш перед анализом. Возможен путь `REFRAME_MODEL`, но файл должен соответствовать тому же манифесту. Пути к FFmpeg можно задать переменными `REFRAME_FFMPEG` и `REFRAME_FFPROBE`.

## Возможности MVP

- 9:16, 16:9, 1:1, 4:5, 4:3; MP4/MOV, H.264 + AAC.
- Входы MP4, MOV, MKV, AVI, WebM и другие контейнеры, которые читает установленный декодер. Вместо ограничения H.264/H.265 программа проверяет декодирование первого кадра через тот же PyAV, что используется при обработке. Проверены SDR H.264/H.265, AV1, VP9, MPEG-4 и ProRes; это не обещание поддержки любого кодека или повреждённого файла.
- Поворот телефона, неквадратные пиксели, переменная частота кадров и видео без звука.
- Оригинальная длительность, порядок кадров и основной звук. Другие звуковые дорожки, вложенные субтитры и служебные метаданные не переносятся.
- Полезное изображение не увеличивается сверх разрешения исходника; разрешение результата зависит от доступной области кадра. Маленькое широкое видео при переводе в вертикальное может дать небольшой выходной файл — это намеренный выбор качества.
- Превью до и после обработки, прогресс каждого этапа, отмена, безопасное сохранение, кнопки открытия результата.
- Во время обработки плеер сохраняет кадр на паузе; изменения прогресса не меняют источник видео и не отправляют повторные команды паузы. Возможности встроенного плеера могут отличаться от декодера экспорта: ошибка предпросмотра сама по себе не запрещает конвертацию.
- При закрытии во время работы можно отменить задание; окно закроется после очистки временных файлов.

Файлы длиннее 10 минут или выше 1080p разрешены с предупреждением. HDR отклоняется. Нет монтажа, ручной рамки, распознавания говорящего, очереди заданий или онлайн-сервисов.

### CPU и NVIDIA

CPU работает по умолчанию. NVENC автоматически проверяется коротким пробным кодированием; при недоступности или ошибке используется libx264. Это независимо от ускорения модели.

Для CUDA нужен совместимый NVIDIA-драйвер и GPU-сборка ONNX Runtime **вместо** CPU-сборки. В отдельном проверяемом окружении можно заменить пакет:

```powershell
.\.venv\Scripts\python.exe -m pip uninstall -y onnxruntime
.\.venv\Scripts\python.exe -m pip install "onnxruntime-gpu[cuda,cudnn]==1.31.0"
```

Приложение пытается предварительно загрузить CUDA/cuDNN DLL, затем создать CUDA-сессию. При неудаче возвращается на CPU. На текущем компьютере только Intel Iris Xe: CUDA и NVENC здесь **не прошли аппаратную приёмку**. Совместимость драйверов и библиотек: [официальная документация ONNX Runtime](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html).

## Как устроено

Интерфейс PySide6/QML общается через события с отдельным процессом задания. Процесс последовательно выполняет проверку → анализ → планирование → рендеринг → добавление звука → проверку результата. Отмена передаётся через process event; FFmpeg останавливается и дожидается завершения перед очисткой.

Анализ использует кадры с длинной стороной не более 640 пикселей, детектор около 5 раз в секунду и проверку смены сцен на каждом декодированном кадре. Координаты переводятся обратно в исходное пространство. Связывание объектов использует класс, прогноз движения и пересечение рамок. Главный объект выбирается по уверенности, размеру, положению и стабильности.

Рамка имеет постоянный размер. Центральная зона допускает небольшое движение без панорамирования. Траектория сглаживается внутри сцены, ограничивается безопасной областью объектов; слишком быстрое движение приводит к полному кадру. Короткие чередования режимов подавляются. Выбор не учитывает звук и не гарантирует понимание сюжетного смысла.

Основные контракты — `VideoInfo`, `AnalysisResult`, `ReframePlan`, `ExportRequest`, `ProgressEvent` в `reframe/contracts.py`. Анализатор не зависит от пропорций и контейнера; рендерер не знает о детекторе; интерфейс не содержит алгоритма кадрирования.

### Добавление формата

- **Новые пропорции:** добавить запись в `reframe/presets.json`: `id`, `title`, `width`, `height`, `description`. Ширина/высота задают предельный размер. Интерфейс строит карточки из этого файла.
- **Новый контейнер:** добавить адаптер в реестр `EXPORTERS` в `reframe/export.py` и проверку его кодеков/мультиплексирования. Существующие MP4/MOV используют общий адаптер; произвольный контейнер может потребовать собственной реализации финализации.
- **Новая модель:** реализовать протокол `Detector.detect(image) -> list[Detection]`, сохранив координаты и уверенность; планировщик и экспорт не меняются.

Состояние GUI сохраняется в `settings.json`, технический журнал — `work/reframe.log`. При обычной ошибке временная папка `.reframe-<id>` рядом с результатом удаляется. При принудительном завершении через диспетчер задач или отключении питания папка может остаться; исходник и существующий результат сохраняются.

## Проверка и диагностика

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts\smoke_ui.py
.\.venv\Scripts\python.exe -m reframe.cli input.mp4 output.mov --preset 9:16 --cpu --diagnostics work\plan.json
```

`--overwrite` явно разрешает замену результата. `--fit-only` — только диагностический режим CLI, отключающий модель; в продуктовый интерфейс он не вынесен.

Для инженерной проверки подготовлены `quality_corpus.py`, `inspect_quality.py` и `benchmark.py`. Первый создаёт 12 сцен с управляемым движением из реальных демонстрационных фотографий; второй считает удержание объекта и создаёт контактный лист; третий проверяет 1080p и длинный файл. Исходные фото необходимо заранее поместить в `work/samples`:

- `dog.jpg`: [пример YOLOX](https://raw.githubusercontent.com/Megvii-BaseDetection/YOLOX/main/assets/dog.jpg).
- `people.jpg`: [пример YOLOv5](https://raw.githubusercontent.com/ultralytics/yolov5/master/data/images/zidane.jpg).

Фото используются только для локальной диагностики; папка `work` не входит в поставку исходного пакета. Они не являются разнообразным набором реальных пользовательских видео. Смешанная приёмка на твоих исходниках и оценка субъективного качества остаются отдельным шагом.

Подробные результаты и ограничения — в `TESTING.md`.
